# Frontend Engineering

Start from user journeys and the existing design system.

## Workflow

1. Identify users, tasks, content hierarchy, device constraints, and loading/empty/error/permission states.
2. Reuse existing tokens and components; define clear component ownership and data flow.
3. Keep server state, URL state, form state, and local UI state distinct.
4. Use semantic HTML, keyboard support, visible focus, labelled controls, appropriate contrast, and assistive-technology announcements.
5. Validate at the client for usability and at the server for trust. Protect against unsafe rendering, token leakage, insecure storage, and unintended cross-origin behaviour.
6. Design responsive layouts from content needs and test real viewport extremes.
7. Budget JavaScript, images, fonts, network waterfalls, and interaction latency; measure before optimising.
8. Test behaviour, accessibility, critical journeys, and representative browsers.

Do not create a generic new visual language when the product already has one. Preserve deep links, refresh behaviour, back navigation, and recoverable form input.
